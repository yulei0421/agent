# Agent 能力缺口与可见计划设计

## 背景

当前项目已经具备 LangGraph 目标拆解、模型自主工具选择、工具超时与取消、失败/陈旧结果收敛、SSE 打字机、金融研究报告和 PDF/PPTX 导出。对照通用研究型 Agent 的使用体验，当前最明显的缺口是：服务端确实生成并推进计划，但用户看不到计划、当前步骤和完成状态。

## 本次接入

增加一个只读的 `plan` SSE 事件：

- 计划最多使用现有 Planner 的三步、每步 120 字限制；
- 每个步骤公开 `pending`、`in_progress`、`completed` 状态；
- 计划生成后立即发送一次，工具轮推进后再次发送；
- 事件不进入模型上下文，不改变工具路由和安全策略；
- 浏览器将最后一次快照保存到当前 assistant 消息，刷新后仍可在本地会话中查看。

增加一个本地失败恢复操作：

- `error` 或 `stopped` 的 assistant 消息显示“重新生成”；
- 操作查找该消息之前最近一条已完成的 user 消息，重新发起普通聊天请求；
- 不覆盖原消息、不改变服务端状态，也不绕过现有工具上限和取消逻辑。

增加研究报告引用账本校验：

- 浏览器从本次请求成功的 `tool_result` 事件收集安全的新闻 `citationId`、天气来源和市场供应商来源。
- 金融研究报告的 `evidence.source` 必须精确匹配该请求的引用账本；未知、伪造或带 URL/IP 的来源不会被解析为结构化研究卡片。
- 账本只保留 ID、展示标签和安全时间元数据，不保留原始 URL、IP、密钥或完整工具结果。

增加受限多 Agent 协作：

- 仅在金融研究模式启动两个固定角色：`researcher` 和 `risk_reviewer`。
- 两个角色并行调用同一个模型端口，但工具清单为空，只能返回最多四条数据需求或风险检查项。
- 子 Agent 输出作为“不可信规划提示”插入主 Agent 的服务端上下文；主 Graph 仍是唯一工具执行者和最终回答者。
- `agent` SSE 事件公开角色的 `started`、`completed`、`failed` 状态，并随当前 assistant 消息保存在浏览器本地。

## 交互

助手消息在正文前显示“任务计划”卡片：

- 未开始步骤显示序号；
- 当前步骤突出显示；
- 已完成步骤显示勾选；
- 全部步骤完成后显示“已完成”。

停止、错误和离线队列状态保留已经收到的计划快照。重新生成会创建新的 user/assistant 消息对，原失败记录仍保留，方便比较两次运行结果。

## 明确不接入

本轮不增加服务端持久化记忆、跨设备会话、后台调度、外部连接器、浏览器自动化、交易执行或人工审批。这些能力需要新的权限、数据保留和运行时边界，不应在当前无账户、无服务端持久化的 Demo 中隐式开启。

## 验证

- SSE 事件运行时校验覆盖计划步骤状态和游标；
- LangGraph 测试验证 Planner 结果会公开为计划快照，工具轮推进会更新快照；
- 前端测试验证计划卡片仅在 assistant 消息存在计划时显示；
- 运行 TypeScript 类型检查、完整测试、Vite 构建和 diff 检查。
