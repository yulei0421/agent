## 仍缺少的能力

以下能力是研究型 Agent 常见的扩展方向，但当前没有偷偷开启：

| 优先级 | 缺口 | 当前原因 | 接入前置 |
| --- | --- | --- | --- |
| P1 | 用户可编辑计划、步骤确认和暂停恢复 | 需要新的交互状态与服务端 checkpoint | 明确是否允许人工审批和持久化状态 |
| P1 | PDF/图片输入与文档检索 | 当前只支持浏览器本地文本附件，不解析二进制文档 | 文件大小、类型、病毒扫描、保留周期 |
| P1 | 连接器/MCP 外部应用 | 当前工具清单为部署期固定六项 | OAuth、权限范围、租户隔离和审计 |
| P2 | 后台长任务、定时任务和通知 | 当前 Agent 状态只存活于单次 HTTP 请求 | 任务队列、任务状态存储、重试和通知通道 |
| P2 | 浏览器/计算机操作 | 当前工具只读且不执行任意网页动作 | 沙箱、域名白名单、人工确认和操作回放 |
| P2 | 多 Agent 分工 | 已接入两个无工具规划子 Agent；尚未支持动态角色发现、子 Agent 独立工具预算和跨任务协作 | 子 Agent 协议、预算、共享上下文和结果合并 |
| P2 | 细粒度来源引用 | 已接入本次请求内的安全引用账本和未知来源拒绝；尚未提供原始来源快照、过期重验证和用户可打开的代理页 | 安全引用代理、来源快照和过期策略 |
| P2 | 多模型路由 | 已接入健康优先的零输出故障切换，尚未支持成本、能力和任务级路由 | 供应商能力声明、成本策略、结构化输出兼容性 |

## 接入原则

1. 先接入不改变现有无账户、无服务端持久化和只读金融工具边界的能力。
2. 涉及权限、文件、外部连接器、浏览器动作或后台任务时，先写清数据保留、取消、审计和人工确认规则。
3. 每个能力必须同时具备端到端测试、失败路径和可观测字段，不能只增加 UI 开关。
4. 交易执行、资金操作和绕过工具白名单不属于本项目的 Agent 能力路线。
